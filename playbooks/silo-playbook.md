# Silo Playbook

A **silo** is a self-contained project directory with named compartments,
each carrying a single responsibility. The `justfile` is the facade that
wires them together.

## The Principle

Every project is a silo. A silo contains all the "stuff" — content, configs,
playbooks, scripts, indexes — organized so an agent can orient within
seconds of running `just help` or `just orient`.

## pob Silo Structure

```
pob/                                 ← Silo root
 ├── content/                        ← Book structure: front-matter, chapters, index
 ├── briefs/                         ← Article drafts and published pieces
 │   └── INDEX.jsonl
 ├── debriefs/                       ← Retrospectives
 │   └── INDEX.jsonl
 ├── decisions/                      ← Architecture decision records
 │   └── INDEX.jsonl
 ├── playbooks/                      ← Operational playbooks
 │   ├── REGISTRY.jsonl
 │   └── *.md
 ├── pdf/                            ← Published PDFs (persistent, tracked)
 ├── dist/                           ← Build output (gitignored)
 ├── src/                            ← SSG source: cli, commands, styles, templates
 │   ├── cli.ts
 │   ├── commands/                   ← build, preview, tree, help, orient
 │   ├── styles/pob.css
 │   ├── templates/layout.html
 │   └── agents/                     ← diagram processing
 ├── build.ts                        ← Core build pipeline (Markdown → HTML + KaTeX)
 ├── justfile                        ← Task runner facade
 ├── .venv/                          ← Python venv for WeasyPrint (gitignored)
 ├── AGENTS.md                       ← Project identity
 └── package.json
```

## Compartments

### Document Compartments (with Indexes)

Every directory that accumulates documents gets an `INDEX.jsonl`:

| Directory | Purpose | Index |
|-----------|---------|-------|
| `briefs/` | Article drafts and published pieces | `INDEX.jsonl` |
| `debriefs/` | Retrospectives | `INDEX.jsonl` |
| `decisions/` | ADRs: why we chose X over Y | `INDEX.jsonl` |
| `playbooks/` | Operational conventions | `REGISTRY.jsonl` |

Schema: `{ file, date, status, summary, meta? }`

### Content Compartments

| Directory | Purpose | Build behaviour |
|-----------|---------|-----------------|
| `content/` | Book structure (front-matter, chapters, index page) | Scanned by `build.ts`, rendered to `dist/` |
| `briefs/` | Standalone articles and essays | Also scanned by `build.ts` (de-duplicated by basename) |
| `pdf/` | Published PDFs | Persistent, tracked in git; generated by `just pdf` |

### Source Compartment

| Directory | Purpose |
|-----------|---------|
| `src/` | SSG source code: CLI, build/preview/tree/orient commands, styles, templates, diagram agents |

### Build Output

| Directory | Purpose |
|-----------|---------|
| `dist/` | Generated HTML + CSS (gitignored, wiped on every `just build`) |

## Justfile Facade

The `justfile` is a **facade** — recipes delegate to `bun run src/cli.ts`.

### Build & Preview

```bash
just build      # Compile markdown → HTML with KaTeX rendering
just preview    # Serve dist/ at localhost:3000
just serve      # Alias for preview
just clean      # Remove dist/
```

### PDF

```bash
just pdf        # Build + render to pdf/ via WeasyPrint
```

### Meta

```bash
just orient     # Bootstrap a new agent (deps, env, intercom, sanity check)
just tree       # Hierarchical view of content/
just check      # Verify the build works
just deps       # Show dependencies
just help       # CLI help
```

## Conventions

### One logical change per commit

All files that must change together, no more. Run `just build` before
and after every commit to verify the pipeline.

### Fail-fast protocol

1. Make small change → `just build` → commit or revert
2. If build fails: revert first, diagnose second
3. If stuck >15 min: stop, revert, ask

### Single source of truth

The build pipeline scans both `content/` and `briefs/` as source directories,
de-duplicated by basename (first dir wins). Do not duplicate files across
the two — if a piece lives in `briefs/`, do not also copy it to `content/`.

### Barnacle detection

Run the barnacle inspection at session start. See `playbooks/barnacle-playbook.md`.
Common targets: blog-posts/Jekyll carry-over, missing file references,
wrong tool defaults, stale paths.

### Registry hygiene

Keep `REGISTRY.jsonl` and `INDEX.jsonl` files in sync with the filesystem.
Stale indexes misdirect agents about what exists in the silo.
